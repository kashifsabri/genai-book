#  Step 4 — Convert Tokens into Embeddings

After tokenization, our sentence looks like this.

```text
Sentence

↓

"I love AI."

↓

Tokens

↓

["I", "love", "AI", "."]

↓

Token IDs

↓

[1045, 2293, 9932, 1012]
```

The model now has numbers.

But there is a problem.

These numbers **do not contain any meaning**.

For example,

```text
1045
```

doesn't tell the model that it represents:

```text
I
```

Similarly,

```text
2293
```

doesn't tell the model that it means:

```text
love
```

They are simply IDs.

The model needs a richer numerical representation.

This is where **Embeddings** come in.

---

# 1.22 What is an Embedding?

An **Embedding** is a dense vector that represents the meaning of a token.

Instead of using a single number,

```text
2293
```

the model converts it into something like:

```text
[0.12, -0.84, 1.57, ..., 0.91]
```

This vector may contain hundreds or even thousands of values.

For example,

GPT-2 uses an embedding size of **768**.

Some larger models use:

- 2048
- 4096
- 8192

dimensions.

The larger the embedding size, the more information each token can represent.

---

# 1.23 Why Are Embeddings Needed?

Imagine assigning every person only an ID.

```text
Person

↓

ID = 25
```

Can you know anything about that person?

No.

Now imagine describing the person using many characteristics.

```text
Height

Age

Language

Profession

City

Experience
```

Now you have much more information.

Embeddings work in a similar way.

Instead of representing a token with one number,

they represent it using hundreds or thousands of numerical features.

This allows the model to capture relationships between words.

---

# 1.24 Example

Suppose we have three words.

```text
King

Queen

Apple
```

After converting them into embeddings,

their vectors may look like this.

```text
King

↓

[0.81, -0.42, 0.91, ...]
```

```text
Queen

↓

[0.79, -0.39, 0.88, ...]
```

```text
Apple

↓

[-0.25, 1.34, -0.61, ...]
```

Notice something interesting.

The embeddings for:

```text
King

Queen
```

are more similar than:

```text
King

Apple
```

This helps the model understand relationships between words.

---

# 1.25 Where Do Embeddings Come From?

The model starts with **random embeddings**.

Example:

```text
King

↓

[0.12, -0.53, 0.88]
```

These values have no useful meaning at the beginning.

During training,

the model repeatedly updates these vectors.

After billions of training steps,

similar words gradually move closer together in the embedding space.

This learning happens automatically.

No one manually assigns these vectors.

---

# 1.26 Positional Encoding

Remember,

embeddings tell the model **what** a token is.

But they don't tell the model **where** the token appears.

Consider these two sentences.

```text
Dog bites man.
```

```text
Man bites dog.
```

Both sentences contain the same words.

But their meanings are completely different because the word order has changed.

To solve this problem,

the model adds **Positional Information** to every embedding.

Now every token contains:

- Meaning (Embedding)
- Position (Positional Encoding or RoPE)

Together, they help the model understand both the word and its position.

---

# 1.27 Output of This Step

After this stage,

every token becomes a vector.

Instead of this,

```text
[1045, 2293, 9932]
```

the model now has something like:

```text
[
 Vector 1,
 Vector 2,
 Vector 3
]
```

These vectors are now ready to enter the Transformer.

---

# 1.28 Real-World Example

Imagine a classroom.

Each student has a roll number.

```text
25
```

The roll number only identifies the student.

Now imagine you also know:

- Name
- Age
- Subjects
- Marks
- Skills

You now understand much more about that student.

Embeddings work in the same way.

They transform simple Token IDs into rich numerical representations.

---

# Engineering Note

The **Embedding Layer** is one of the trainable parts of an LLM.

During training,

its values are updated through backpropagation just like every other neural network layer.

As training progresses,

the embeddings become better at capturing the meaning and relationships between words.

---

# What's Next?

The model now has embeddings for every token.

These embeddings are passed into the Transformer.

The Transformer processes them using:

- Self-Attention
- Feed Forward Networks
- Residual Connections
- Layer Normalization

This entire process is called the **Forward Pass**.
