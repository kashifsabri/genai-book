# 10. Quantization

## Introduction

Modern Large Language Models are extremely large.

For example,

- Llama 3 8B → 8 Billion parameters
- Llama 3 70B → 70 Billion parameters

Running these models requires a lot of GPU memory.

This creates a problem.

Not everyone has expensive GPUs with large amounts of memory.

So how can we run these models on:

- A laptop?
- A gaming PC?
- A smaller GPU?
- An edge device?

The answer is **Quantization**.

Quantization reduces the size of a model so it can run faster and use less memory.

---

# 10.1 Why Do We Need Quantization?

Let's understand the problem first.

Suppose every parameter in a model is stored using **32 bits (FP32)**.

If a model has:

```text
8 Billion Parameters
```

then storing all those parameters requires a huge amount of memory.

A larger model requires even more memory.

This makes it difficult to run large models on normal computers.

Quantization solves this problem by storing each parameter using fewer bits.

---

# 10.2 What is Quantization?

Quantization is the process of converting model weights from a **higher precision** format to a **lower precision** format.

For example,

Before:

```text
FP32
```

After:

```text
INT8
```

or

```text
INT4
```

The model becomes much smaller while still producing similar results.

Think of it as **compressing the model**.

---

# 10.3 An Easy Example

Imagine you have a photo.

Original Photo:

```text
20 MB
```

You compress it.

Compressed Photo:

```text
5 MB
```

The photo still looks almost the same.

It just takes less storage.

Quantization works in a similar way.

The model becomes smaller while trying to keep almost the same performance.

---

# 10.4 Understanding Precision

Computers store numbers using different formats.

Some common formats are:

| Format | Bits Used |
|---------|----------:|
| FP32 | 32 Bits |
| FP16 | 16 Bits |
| BF16 | 16 Bits |
| INT8 | 8 Bits |
| INT4 | 4 Bits |

Notice something.

As the number of bits decreases,

the memory required also decreases.

---

# 10.5 How Does Quantization Reduce Memory?

Suppose one weight is stored as:

```text
0.83726451
```

This uses high precision.

After quantization,

it may become:

```text
0.84
```

or even

```text
1
```

The value is slightly less accurate,

but it requires much less memory.

Now imagine doing this for **billions of weights**.

The memory savings become huge.

---

# 10.6 Does Quantization Change the Model?

No.

The model architecture stays exactly the same.

Only the way the weights are stored changes.

Before:

```text
Transformer

↓

FP32 Weights
```

After:

```text
Transformer

↓

INT8 Weights
```

The layers remain the same.

The attention mechanism remains the same.

Only the numerical representation changes.

---

# 10.7 Benefits of Quantization

Quantization offers several advantages.

- Smaller model size
- Lower GPU memory usage
- Faster inference
- Lower deployment cost
- Can run on consumer hardware

This is why quantization is widely used in production.

---

# 10.8 Are There Any Disadvantages?

Yes.

Since the numbers become less precise,

the model may lose a small amount of accuracy.

Think of it like compressing an image.

A compressed image saves storage,

but too much compression may reduce image quality.

Similarly,

extreme quantization may slightly reduce the model's performance.

The goal is to find a good balance between:

- Speed
- Memory
- Accuracy

---

# 10.9 Python Example

Load a model using 8-bit quantization.

```python
from transformers import AutoModelForCausalLM

model = AutoModelForCausalLM.from_pretrained(
    "meta-llama/Llama-3-8B",
    load_in_8bit=True
)
```

Load a model using 4-bit quantization.

```python
model = AutoModelForCausalLM.from_pretrained(
    "meta-llama/Llama-3-8B",
    load_in_4bit=True
)
```

These options reduce the amount of GPU memory required.

---

# 10.10 Real-World Example

Imagine moving to a new house.

You have two options.

Option 1

Carry every item exactly as it is.

It takes many trips.

Option 2

Pack your belongings into compact boxes.

Now you need fewer trips.

Nothing important has changed.

The items are simply packed more efficiently.

Quantization works in the same way.

It packs the model into a smaller form so it can run more efficiently.

# Common Beginner Mistakes

### Mistake 1

Thinking quantization changes the model architecture.

It doesn't.

Only the weights are stored differently.

---

### Mistake 2

Thinking quantization always reduces accuracy significantly.

In many cases, the accuracy drop is very small.

---

### Mistake 3

Thinking quantization is only used for small devices.

It is also widely used in cloud deployments to reduce memory and cost.

---

# Key Takeaways

- Quantization reduces the size of an LLM.
- It stores weights using fewer bits.
- Smaller models require less memory.
- Quantized models usually run faster.
- The model architecture remains unchanged.
- There is a trade-off between memory usage and accuracy.
