# 11. Quantization Techniques

## Introduction

In the previous chapter, we learned what Quantization is.

We learned that it reduces the size of a model by storing its weights using fewer bits.

Now let's learn **how quantization is actually performed**.

There isn't just one way to quantize a model.

Different techniques are used depending on:

- When the model is quantized
- How the weights are stored
- Whether the model is being trained or only used for inference

---

# 11.1 Dynamic Quantization

Dynamic Quantization is one of the simplest quantization techniques.

In this method:

- The model is trained normally.
- Quantization happens only during inference.

The weights are stored in a lower precision format, while some calculations are performed dynamically during execution.

Think of it like this:

```text
Train Model

↓

Save Model

↓

Quantize During Inference
```

---

## When is it Used?

Dynamic Quantization is useful when you want:

- Easy deployment
- Lower memory usage
- Minimal changes to the original model

It is commonly used for smaller neural networks.

Large LLMs usually use more advanced techniques.

---

# 11.2 Static Quantization

Static Quantization performs quantization **before inference starts**.

Instead of waiting until runtime,

the model is already converted into a lower precision format.

```text
Train Model

↓

Quantize Model

↓

Deploy Model
```

Because everything is prepared in advance,

inference is usually faster.

---

# Dynamic vs Static Quantization

| Dynamic | Static |
|----------|---------|
| Quantization happens during inference | Quantization happens before inference |
| Easier to apply | Requires more preparation |
| Good for simple deployment | Usually provides better performance |

---

# 11.3 Weight-Only Quantization

Remember,

an LLM mainly consists of:

- Weights
- Activations

Weight-Only Quantization compresses **only the weights**.

The activations remain in higher precision.

```text
Weights

↓

INT4 / INT8
```

```text
Activations

↓

FP16 / BF16
```

This approach is very popular because:

- It greatly reduces memory usage.
- It usually maintains good model quality.

Many modern LLM quantization methods use this approach.

---

# 11.4 Post-Training Quantization (PTQ)

Suppose you already have a trained model.

Example:

```text
Llama

↓

Training Finished
```

Now you want to reduce its size.

You don't want to train it again.

Instead,

you directly quantize the trained model.

This is called **Post-Training Quantization (PTQ).**

```text
Train Model

↓

Finished

↓

Quantize

↓

Deploy
```

This is the most common approach for deploying open-source LLMs.

---

# 11.5 Quantization-Aware Training (QAT)

Now consider a different situation.

Instead of quantizing the model after training,

the model is trained while being aware that it will be quantized.

This is called **Quantization-Aware Training (QAT).**

```text
Training

↓

Quantization is considered during training

↓

Better final accuracy
```

Because the model learns with quantization in mind,

it often performs better after quantization.

The downside is that training becomes more complex.

---

# PTQ vs QAT

| PTQ | QAT |
|------|-----|
| Quantize after training | Quantize during training |
| Simple | More complex |
| No retraining required | Requires training |
| Very common for LLM deployment | Used when maximum accuracy is needed |

---

# 11.6 Which Technique is Used Most?

For most developers,

the workflow looks like this.

```text
Download Pretrained Model

↓

Apply PTQ

↓

Deploy
```

This is much easier than training a model again.

Large companies training their own models may use QAT,

but most developers work with PTQ.

---

# Python Example

Using Hugging Face with BitsAndBytes.

```python
from transformers import AutoModelForCausalLM
from transformers import BitsAndBytesConfig

config = BitsAndBytesConfig(
    load_in_4bit=True
)

model = AutoModelForCausalLM.from_pretrained(
    "meta-llama/Llama-3-8B",
    quantization_config=config
)
```

The model is loaded in a quantized format, reducing GPU memory usage.

# Real-World Example

Imagine buying a large suitcase.

### PTQ

You pack the suitcase after buying all your clothes.

```text
Buy Clothes

↓

Pack Suitcase
```

### QAT

You know the suitcase is small before shopping.

So you buy clothes that fit more efficiently.

```text
Know Suitcase Size

↓

Buy Suitable Clothes

↓

Pack Easily
```

QAT plans ahead.

PTQ packs afterward.

# Common Beginner Mistakes

### Mistake 1

Thinking PTQ and QAT produce the same results.

They have the same goal but use different approaches.

---

### Mistake 2

Thinking QAT is always better.

It often gives better accuracy, but it also requires additional training time and compute.

---

### Mistake 3

Thinking Weight-Only Quantization changes every part of the model.

It only compresses the model's weights.

---

# Key Takeaways

- There are multiple ways to quantize a model.
- Dynamic Quantization happens during inference.
- Static Quantization happens before inference.
- Weight-Only Quantization compresses only the model weights.
- PTQ quantizes a model after training.
- QAT considers quantization during training for better accuracy.
- Most developers use PTQ because it is simple and practical.
