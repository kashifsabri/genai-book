# 7. LLM Inference Pipeline

## Introduction

So far, we've learned how an LLM is trained.

After training is complete, the model is ready to answer user questions.

This stage is called **Inference**.

**Inference** means using a trained model to make predictions.

Unlike training, inference **does not update the model's weights**.

The model simply uses the knowledge it has already learned.

Every time you use ChatGPT, Gemini, Claude, or Llama, you are performing inference.

---

# 7.1 What is Inference?

Inference is the process of generating predictions using a trained model.

For example,

User Prompt:

```text
What is Machine Learning?
```

The model generates:

```text
Machine Learning is a branch of Artificial Intelligence that enables computers to learn from data.
```

The model is **not learning** anything new.

It is simply using its existing knowledge.

---

# 7.2 Training vs Inference

| Training | Inference |
|----------|-----------|
| Model learns | Model predicts |
| Weights are updated | Weights remain unchanged |
| Uses backpropagation | No backpropagation |
| Uses optimizer | No optimizer |
| Very expensive | Much faster |

Remember:

**Training = Learning**

**Inference = Using what was learned**

---

# 7.3 The LLM Inference Pipeline

When a user enters a prompt, several steps happen before the answer appears.

```text
User Prompt
      │
      ▼
Tokenizer
      │
      ▼
Token IDs
      │
      ▼
Embedding Layer
      │
      ▼
Transformer
      │
      ▼
Next Token Prediction
      │
      ▼
Decode Token IDs
      │
      ▼
Generated Text
```

Let's understand each step.

---

# 7.4 Step 1 — User Enters a Prompt

Suppose the user types:

```text
Explain Artificial Intelligence.
```

This is called the **Prompt**.

The model cannot understand plain text directly.

---

# 7.5 Step 2 — Tokenization

The tokenizer converts the text into tokens.

```text
Explain

Artificial

Intelligence

.
```

Then it converts them into Token IDs.

Example:

```text
[2050, 7976, 4454, 1012]
```

These IDs become the input to the model.

---

# 7.6 Step 3 — Create Embeddings

Each Token ID is converted into an embedding.

Example:

```text
2050

↓

[0.41, -0.23, 0.98, ...]
```

Now every token has a meaningful numerical representation.

---

# 7.7 Step 4 — Run the Transformer

The embeddings pass through all Transformer layers.

Inside each layer, the model performs:

- Self-Attention
- Feed Forward Network
- Residual Connections
- Layer Normalization

By the end of the forward pass, the model understands the context of the prompt.

---

# 7.8 Step 5 — Predict the Next Token

The model predicts the most likely next token.

Example:

Prompt:

```text
The capital of France is
```

Prediction:

```text
Paris
```

The prediction is based on probabilities.

---

# 7.9 Step 6 — Add the New Token

The predicted token is added to the sentence.

Before:

```text
The capital of France is
```

After:

```text
The capital of France is Paris
```

The updated sentence is sent back into the model.

---

# 7.10 Step 7 — Repeat the Process

The model predicts one token at a time.

```text
Prompt
      │
      ▼
Predict Token 1
      │
      ▼
Add Token
      │
      ▼
Predict Token 2
      │
      ▼
Add Token
      │
      ▼
Predict Token 3
      │
      ▼
Continue...
```

This continues until the model decides to stop or reaches the maximum token limit.

---

# 7.11 Python Example

Load a pretrained model.

```python
from transformers import AutoTokenizer
from transformers import AutoModelForCausalLM

tokenizer = AutoTokenizer.from_pretrained("gpt2")
model = AutoModelForCausalLM.from_pretrained("gpt2")
```

Tokenize the prompt.

```python
prompt = "The capital of France is"

inputs = tokenizer(
    prompt,
    return_tensors="pt"
)
```

Generate a response.

```python
output = model.generate(
    **inputs,
    max_new_tokens=20
)
```

Convert the output back to text.

```python
response = tokenizer.decode(
    output[0],
    skip_special_tokens=True
)

print(response)
```

Possible Output:

```text
The capital of France is Paris.
```

---

# 7.12 Why Is Inference Faster Than Training?

During inference:

- No loss is calculated.
- No backpropagation happens.
- No optimizer updates the weights.

The model only performs a forward pass.

This is why inference is much faster than training.

---

# 7.13 Real-World Example

Imagine a student taking an exam.

During preparation:

- The student studies.
- Learns from mistakes.
- Improves knowledge.

This is like **training**.

During the exam:

- The student simply answers questions.
- No learning takes place.

This is like **inference**.

# 7.14 Where Does Decoding Fit?

So far, we've said:

```text
Predict Next Token
```

But one question remains.

**How does the model decide which token to choose?**

Should it always choose the highest probability?

Or should it sometimes choose a less likely token to produce more creative responses?

This decision is made using **Decoding Strategies**.

We'll study them in the next chapter.

---

# Common Beginner Mistakes

### Mistake 1

Thinking the model learns during inference.

It doesn't.

The weights never change during inference.

---

### Mistake 2

Thinking the model generates the entire sentence at once.

It doesn't.

It generates **one token at a time**.

---

### Mistake 3

Thinking inference requires backpropagation.

Backpropagation is only used during training.

---

# Key Takeaways

- Inference is the process of using a trained model to generate predictions.
- During inference, the model performs only a forward pass.
- The model predicts one token at a time.
- Each predicted token is added back to the input to generate the next token.
- No learning or weight updates happen during inference.
- The next token is selected using a decoding strategy, which we'll learn in the next chapter.
