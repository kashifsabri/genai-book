

## Introduction

In the previous chapter, we learned what a Vector Database is.

Now let's use one.

The first Vector Database we'll learn is **FAISS**.

FAISS is one of the most popular libraries for storing and searching embeddings locally.

It is:

- Free
- Fast
- Open Source
- Developed by Meta (Facebook)

Many developers use FAISS while learning RAG because it is simple and doesn't require a cloud account.

---

# 8.1 What is FAISS?

FAISS stands for:

**Facebook AI Similarity Search**

It is a library designed to:

- Store embeddings
- Search embeddings
- Find the nearest vectors quickly

Think of FAISS as a local search engine for embeddings.

Instead of searching files,

it searches vectors.

---

# 8.2 Why Do We Need FAISS?

Suppose you have:

```text
10 Documents
```

Searching is easy.

Now imagine:

```text
1 Million Documents
```

Comparing your question with every embedding one by one would be very slow.

FAISS creates an efficient index so it can quickly find the most similar vectors.

Think of it like a book index.

Without an index,

you read every page.

With an index,

you jump directly to the correct page.

---

# 8.3 How FAISS Fits into RAG

During indexing:

```text
Documents
      │
      ▼
Chunking
      │
      ▼
Embeddings
      │
      ▼
FAISS Index
```

During retrieval:

```text
User Question
      │
      ▼
Embedding
      │
      ▼
FAISS Search
      │
      ▼
Top Matching Chunks
      │
      ▼
LLM
```

FAISS is responsible only for storing and searching vectors.

It does **not** generate answers.

The LLM still generates the final response.

```python
documents = [
    "Employees receive 24 paid leave days every year.",
    "Office timings are from 9 AM to 6 PM.",

    "The dress code is business casual."
]
```

---

# 8.7 Create a FAISS Vector Store

Import FAISS.

```python
from langchain_community.vectorstores import FAISS
```

Create the vector store.

```python
vector_store = FAISS.from_texts(
    texts=documents,
    embedding=embeddings
)
```

What happens internally?

```text
Documents
      │
      ▼
Generate Embeddings
      │
      ▼
Create FAISS Index
      │
      ▼
Store Embeddings
```

All of this happens automatically.

---

# 8.8 Perform Similarity Search

Now let's ask a question.

```python
query = "How many vacation days do employees receive?"

results = vector_store.similarity_search(
    query=query,
    k=2
)
```

Display the results.

```python
for document in results:
    print(document.page_content)
```

Possible Output

```text
Employees receive 24 paid leave days every year.

Employees can work remotely twice a week.
```

FAISS returns the most relevant document chunks.

---

# 8.9 Search With Similarity Scores

Sometimes we also want to know **how confident** FAISS is.

```python
results = vector_store.similarity_search_with_score(
    query,
    k=2
)
```

Display the score.

```python
for document, score in results:
    print(score)
    print(document.page_content)
```

Example Output

```text
0.18
Employees receive 24 paid leave days every year.

0.77
Employees can work remotely twice a week.
```

The exact meaning of the score depends on the distance metric used internally.

Generally, the best match appears first.

---

# 8.10 Save the FAISS Index

Suppose you've already created your vector database.

You don't want to recreate it every time your application starts.

Save it to disk.

```python
vector_store.save_local("faiss_index")
```

A folder named:

```text
faiss_index/
```

will be created.

---

# 8.11 Load an Existing FAISS Index

Later,

instead of rebuilding everything,

simply load it.

```python
vector_store = FAISS.load_local(
    "faiss_index",
    embeddings,
    allow_dangerous_deserialization=True
)
```

Now your application is ready immediately.

# Limitations of FAISS

FAISS is excellent for learning and local applications.

However,

it has some limitations.

- Mainly designed for local storage.
- Doesn't provide cloud hosting.
- Doesn't include user management.
- Doesn't include automatic backups.

For production cloud applications,

developers often use databases like:

- Pinecone
- Weaviate
- Qdrant

# Common Beginner Mistakes

### Mistake 1

Thinking FAISS is an LLM.

It isn't.

FAISS only stores and searches embeddings.

---

### Mistake 2

Thinking FAISS generates answers.

It doesn't.

It retrieves relevant document chunks.

The LLM generates the final answer.

---

### Mistake 3

Rebuilding the FAISS index every time the application starts.

Instead,

save the index once and load it when needed.
