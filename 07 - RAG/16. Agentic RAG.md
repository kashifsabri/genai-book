
## Introduction

So far, our RAG system works like this:

```text
User Question
      │
      ▼
Retriever
      │
      ▼
Relevant Documents
      │
      ▼
LLM
      │
      ▼
Answer
```

This works well for simple questions.

For example:

```text
How many paid leave days do employees receive?
```

The Retriever finds the relevant document.

The LLM answers.

Done.

But what happens if the question is more complex?

Example:

```text
Which employees worked on Project Phoenix and later moved to the HR department?
```

One search may not be enough.

The AI may need to:

- Search multiple documents
- Think about the results
- Search again
- Use external tools
- Verify the answer

This is where **Agentic RAG** comes in.

---

# 16.1 What is Agentic RAG?

Agentic RAG combines:

- RAG
- AI Agents

Instead of retrieving information only once,

the AI agent can decide:

- Should I search again?
- Should I search a different document?
- Should I use another tool?
- Do I have enough information?

The AI becomes an active problem solver instead of following a fixed pipeline.

---

# 16.2 Traditional RAG vs Agentic RAG

Traditional RAG

```text
Question

↓

Retrieve Once

↓

LLM

↓

Answer
```

Agentic RAG

```text
Question

↓

Plan

↓

Retrieve

↓

Think

↓

Need More Information?

↓

Yes

↓

Retrieve Again

↓

Use Tools

↓

Generate Answer
```

The biggest difference is that Agentic RAG can perform **multiple retrieval steps** before answering.

---

# 16.3 Components of Agentic RAG

A typical Agentic RAG system contains:

- Planner
- Retriever
- Tool Executor
- Memory
- LLM

Each component has a specific role.

---

# 16.4 Planner

The Planner decides what needs to happen.

Example:

User asks:

```text
Summarize last month's HR reports and compare them with Finance reports.
```

The Planner may create this plan.

```text
Step 1

Retrieve HR reports.
```

↓

```text
Step 2

Retrieve Finance reports.
```

↓

```text
Step 3

Compare both.
```

↓

```text
Generate summary.
```

Instead of one search,

multiple searches are performed.

---

# 16.5 Retriever

The Retriever searches the knowledge base.

Unlike traditional RAG,

the Retriever may be called multiple times.

Example:

```text
Search HR Reports
```

↓

```text
Search Finance Reports
```

↓

```text
Search Company Policies
```

Each search provides more information.

---

# 16.6 Tool Calling

Sometimes the answer isn't in the documents.

The AI may need external tools.

Examples:

- Calculator
- Database
- Weather API
- SQL
- Python
- Search Engine

Example

```text
User:

What is today's stock price?
```

The AI calls:

```text
Stock Market API
```

instead of guessing.

---

# 16.7 Memory

The agent remembers previous steps.

Example

```text
Retrieved:

HR Report
```

↓

```text
Retrieved:

Finance Report
```

↓

```text
Compare both reports
```

Without memory,

the agent would forget earlier results.

---

# 16.8 Reflection

Sometimes the AI realizes:

```text
I don't have enough information.
```

Instead of answering immediately,

it searches again.

Example

```text
Question

↓

Retrieve

↓

Not Enough Information

↓

Retrieve Again

↓

Answer
```

This process is called **Reflection** or **Self-Correction**.

---

# 16.9 Agentic RAG Workflow

```text
User Question
      │
      ▼
Planner
      │
      ▼
Retriever
      │
      ▼
Memory
      │
      ▼
Need Another Search?
      │
   Yes │ No
      ▼
Tool Calling
      │
      ▼
LLM
      │
      ▼
Answer
```

Notice that the workflow is no longer linear.

The agent can loop until it has enough information.

# 16.11 When Should You Use Agentic RAG?

Use Agentic RAG when:

- Questions require multiple searches.
- Multiple tools are needed.
- The workflow involves planning.
- The AI needs to verify information before answering.

For simple document Q&A,

traditional RAG is often enough.

---

# 16.12 Mini Project (Concept)

Imagine a company assistant.

The user asks:

```text
Compare this month's HR policy changes with last month's version and summarize the differences.
```

The agent could:

1. Retrieve last month's policy.
2. Retrieve this month's policy.
3. Compare the two documents.
4. Generate a summary.

A traditional RAG system would struggle with this because it retrieves only once.

An Agentic RAG system can perform each step in sequence.

---

# Real-World Example

Imagine a detective solving a case.

The detective doesn't stop after finding one clue.

Instead, they:

- Collect evidence.
- Interview witnesses.
- Verify facts.
- Search for missing information.
- Connect the evidence.
- Then reach a conclusion.

Traditional RAG is like reading one file.

Agentic RAG is like conducting a full investigation.

# Common Beginner Mistakes

### Mistake 1

Thinking Agentic RAG replaces RAG.

It doesn't.

It extends RAG by adding planning, memory, and tool use.

---

### Mistake 2

Thinking every chatbot needs Agentic RAG.

Many simple document Q&A systems work perfectly with traditional RAG.

Use Agentic RAG only when tasks require multiple reasoning or retrieval steps.

---

### Mistake 3

Thinking Agentic RAG always performs multiple searches.

It can, but it doesn't have to.

The agent decides whether another retrieval step is necessary.

---

# Key Takeaways

- Agentic RAG combines retrieval with agent capabilities.
- The agent can plan, retrieve multiple times, use tools, remember previous results, and verify information.
- Agentic RAG is useful for complex, multi-step tasks.
- Traditional RAG is often sufficient for simple question-answering.
- Agentic RAG is the foundation of many modern enterprise AI systems.
