

## Introduction

In the previous chapter, we learned what a Retriever is.

A Retriever searches the Vector Database and returns the most relevant document chunks.

But here's an important question.

> **How does the Retriever decide which documents are relevant?**

There isn't just one way to retrieve documents.

Different applications use different retrieval techniques.

The three most common techniques are:

- Dense Retrieval
- Sparse Retrieval (BM25)
- Hybrid Retrieval

Let's understand each one.

---

# 12.1 Dense Retrieval

Dense Retrieval uses **Embeddings**.

Remember,

during indexing,

every document was converted into an embedding.

Example

```text
Leave Policy

↓

[0.42, -0.71, 0.18, ...]
```

When the user asks a question,

the question is also converted into an embedding.

Example

```text
How many vacation days do employees receive?

↓

[0.39, -0.75, 0.21, ...]
```

The Retriever compares these vectors.

The most similar vectors are returned.

---

## Example

Document

```text
Employees receive 24 paid leave days every year.
```

Question

```text
How many vacation days do employees receive?
```

Notice something.

The words are different.

```text
Paid Leave

≠

Vacation Days
```

But the meaning is similar.

Dense Retrieval understands meaning,

so it retrieves the correct document.

---

## Advantages

- Understands meaning
- Works well with different wording
- Excellent for RAG

---

## Limitations

- Requires embeddings
- Slightly slower than keyword search
- Needs a Vector Database

---

# 12.2 Sparse Retrieval (BM25)

Sparse Retrieval works differently.

Instead of understanding meaning,

it searches for **matching words**.

Example

Document

```text
Employees receive 24 paid leave days.
```

Question

```text
paid leave
```

Because the words match,

the document is retrieved.

---

## Another Example

Question

```text
vacation days
```

Document

```text
paid leave
```

The words don't match exactly.

BM25 may fail.

This is one of its biggest limitations.

---

## Advantages

- Fast
- Doesn't require embeddings
- Good for keyword search

---

## Limitations

- Doesn't understand meaning
- Sensitive to wording
- Can miss relevant documents

---

# 12.3 Dense vs Sparse

| Dense Retrieval | Sparse Retrieval |
|-----------------|------------------|
| Uses embeddings | Uses keywords |
| Understands meaning | Matches words |
| Needs Vector DB | Doesn't need embeddings |
| Better for RAG | Better for exact keyword search |

---

# 12.4 Hybrid Retrieval

Instead of choosing one,

why not use both?

Hybrid Retrieval combines:

```text
Dense Retrieval

+

Sparse Retrieval
```

Now the Retriever benefits from both.

It understands:

- Meaning
- Exact keywords

Example

User asks

```text
What is the HR leave policy?
```

Dense Retrieval finds documents about:

```text
Vacation
Leave
Paid Leave
Time Off
```

Sparse Retrieval gives extra importance to:

```text
HR
```

The final result is usually much better.

---

# Why Do Companies Use Hybrid Search?

Companies often have:

- Product names
- Employee IDs
- Invoice numbers
- Policy numbers

Example

```text
HR-102
```

Embeddings may not understand this code well.

Keyword search finds it immediately.

Hybrid Search combines:

- Semantic understanding
- Exact matching

This is why many production RAG systems use Hybrid Search.

# 12.6 Python Example (Sparse Retrieval using BM25)

```bash
pip install rank-bm25
```

```python
from rank_bm25 import BM25Okapi

documents = [
    "Employees receive 24 paid leave days.",
    "Office timings are from 9 AM to 6 PM.",
    "Employees can work remotely."
]

tokenized_docs = [doc.split() for doc in documents]

bm25 = BM25Okapi(tokenized_docs)

query = "paid leave".split()

scores = bm25.get_scores(query)

print(scores)
```

# 12.7 Hybrid Retrieval

```text

+

Final Ranking
```

Frameworks like LangChain and enterprise search engines can combine these methods automatically.

# Common Beginner Mistakes

### Mistake 1

Thinking Dense Retrieval always beats BM25.

Not always.

For exact IDs, codes, or product names, BM25 can perform better.

---

### Mistake 2

Thinking BM25 understands meaning.

It doesn't.

It mainly matches keywords.

---

### Mistake 3

Thinking Hybrid Retrieval is a new database.

It isn't.

It is a retrieval strategy that combines Dense and Sparse Retrieval.

---

# Key Takeaways

- Dense Retrieval uses embeddings.
- Sparse Retrieval (BM25) uses keyword matching.
- Hybrid Retrieval combines both approaches.
- Dense Retrieval is best for semantic search.
- BM25 is best for exact keyword matching.
- Hybrid Retrieval is widely used in production RAG systems.
