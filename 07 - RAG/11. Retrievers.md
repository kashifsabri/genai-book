
## Introduction

In the previous chapters, we learned:

- Documents are converted into embeddings.
- Embeddings are stored in a Vector Database.

Now another question arises.

Suppose your Vector Database contains:

```text
5 Million Document Chunks
```

How does the system decide **which chunks should be sent to the LLM?**

The answer is:

**Retriever**

A Retriever is responsible for searching the Vector Database and returning the most relevant document chunks.

---

# 11.1 What is a Retriever?

A Retriever is a component that searches the Vector Database for documents that are most relevant to the user's question.

Think of it as a librarian.

Suppose you ask:

```text
Do you have a book about Python?
```

The librarian doesn't answer your question.

Instead,

the librarian finds the correct books and gives them to you.

Similarly,

the Retriever doesn't generate answers.

It only finds relevant documents.

The LLM then uses those documents to generate the answer.

---

# 11.2 Retriever in the RAG Pipeline

The Retriever sits between the Vector Database and the LLM.

```text
User Question
      │
      ▼
Embedding
      │
      ▼
Vector Database
      │
      ▼
Retriever
      │
      ▼
Relevant Chunks
      │
      ▼
LLM
      │
      ▼
Answer
```

Without a Retriever,

the LLM wouldn't know which documents to read.

---

# 11.3 Retriever vs Vector Database

Many beginners confuse these two.

They are different.

| Vector Database | Retriever |
|-----------------|-----------|
| Stores embeddings | Searches embeddings |
| Stores documents | Retrieves documents |
| Contains the data | Finds the data |

Think of it like this.

The Vector Database is the **library**.

The Retriever is the **librarian**.

---

# 11.4 What Happens Inside a Retriever?

Suppose the user asks:

```text
How many leave days do employees receive?
```

The Retriever performs these steps.

```text
User Question
      │
      ▼
Generate Embedding
      │
      ▼
Search Vector Database
      │
      ▼
Rank Results
      │
      ▼
Return Top Documents
```

The LLM receives only the retrieved documents.

---

# 11.5 How Many Documents Should We Retrieve?

Suppose we retrieve:

```text
1 Document
```

The answer may miss important information.

Now suppose we retrieve:

```text
100 Documents
```

The LLM receives too much context.

This increases:

- Cost
- Latency
- Token usage

Usually,

developers retrieve only the **Top K** documents.

Example:

```text
Top 3
```

or

```text
Top 5
```

---

# 11.6 Using a Retriever in LangChain

Suppose we already have a Chroma Vector Database.

```python
from langchain_chroma import Chroma
from langchain_huggingface import HuggingFaceEmbeddings

embeddings = HuggingFaceEmbeddings(
    model_name="sentence-transformers/all-MiniLM-L6-v2"
)

documents = [
    "Employees receive 24 paid leave days every year.",
    "Office timings are from 9 AM to 6 PM.",
    "Employees can work remotely twice a week."
]

vector_store = Chroma.from_texts(
    texts=documents,
    embedding=embeddings
)
```

Create a Retriever.

```python
retriever = vector_store.as_retriever()
```

That's it.

The Vector Store has now become a Retriever.

---

# 11.7 Retrieving Documents

Ask a question.

```python
query = "How many vacation days do employees receive?"
```

Retrieve documents.

```python
results = retriever.invoke(query)
```

Display the results.

```python
for document in results:
    print(document.page_content)
```

Output

```text
Employees receive 24 paid leave days every year.
```

Notice that we didn't call:

```python
similarity_search()
```

Instead,

we used:

```python
retriever.invoke()
```

This is the recommended approach in modern LangChain.

---

# 11.8 Configuring the Retriever

We can control how many documents are returned.

```python
retriever = vector_store.as_retriever(
    search_kwargs={"k": 3}
)
```

Now the Retriever returns the top three matching documents.

---

# 11.9 Different Retrieval Strategies

A Retriever can use different search methods.

For example:

- Similarity Search
- Maximum Marginal Relevance (MMR)
- Similarity Score Threshold

Example:

```python
retriever = vector_store.as_retriever(
    search_type="mmr"
)
```

We'll study these retrieval strategies in the upcoming chapters.

# 11.10 Mini Project — Build a Document Retriever

Let's build a simple Retriever.

---

### Step 1

Create sample documents.

```python
documents = [
    "Employees receive 24 paid leave days every year.",
    "Office timings are from 9 AM to 6 PM.",
    "Employees can work remotely twice a week.",
    "The dress code is business casual."
]
```

---

### Step 2

Create embeddings.

```python
from langchain_huggingface import HuggingFaceEmbeddings

embeddings = HuggingFaceEmbeddings(
    model_name="sentence-transformers/all-MiniLM-L6-v2"
)
```

---

### Step 3

Create a Chroma Vector Database.

```python
from langchain_chroma import Chroma

vector_store = Chroma.from_texts(
    texts=documents,
    embedding=embeddings
)
```

---

### Step 4

Create a Retriever.

```python
retriever = vector_store.as_retriever(
    search_kwargs={"k": 2}
)
```

---

### Step 5

Ask a question.

```python
query = input("Ask a question: ")
```

---

### Step 6

Retrieve documents.

```python
results = retriever.invoke(query)
```

---

### Step 7

Display the retrieved documents.

```python
print("\nRetrieved Documents:\n")

for document in results:
    print(document.page_content)
```

Example

```text
Ask a question

How many vacation days do employees receive?
```

Output

```text
Retrieved Documents

Employees receive 24 paid leave days every year.

Employees can work remotely twice a week.
```

Congratulations!

You have built your first Retriever.

Notice something important.

The Retriever only returns relevant documents.

It does **not** generate the final answer.

That is still the LLM's job.

# Common Beginner Mistakes

### Mistake 1

Thinking the Retriever stores documents.

It doesn't.

The Vector Database stores documents.

The Retriever searches them.

---

### Mistake 2

Thinking the Retriever generates answers.

It doesn't.

The LLM generates answers.

---

### Mistake 3

Returning too many documents.

Sending too many chunks increases cost and may reduce answer quality.

---

# Key Takeaways

- A Retriever searches a Vector Database for relevant documents.
- It sits between the Vector Database and the LLM.
- Retrievers do not generate answers.
- LangChain makes it easy to convert a Vector Store into a Retriever.
- Retrievers are a core component of every RAG application.
