

## Introduction

So far, our RAG system retrieves documents based on semantic similarity.

This works well for many questions.

However, some questions require understanding **relationships** between different pieces of information.

For example:

```text
Who manages the employee that worked on Project Phoenix?
```

The answer may require connecting:

- Employee
- Project
- Manager

A traditional RAG system may struggle because this information is spread across multiple documents.

This is where **Knowledge Graphs** become useful.

---

# 15.1 What is a Knowledge Graph?

A Knowledge Graph stores information as **connected entities**.

Instead of storing only documents,

it stores:

- Things (Entities)
- Relationships between those things

Imagine a family tree.

```text
John

│

Father Of

│

Alice
```

Instead of reading an entire document,

the system already knows that:

```text
John → Father Of → Alice
```

This makes relationship-based questions much easier to answer.

---

# 15.2 Basic Components

A Knowledge Graph has three main components.

### Entity (Node)

A real-world object.

Examples:

```text
Employee
```

```text
Project
```

```text
Department
```

---

### Relationship (Edge)

Connects two entities.

Example

```text
Alice

WORKS_IN

HR
```

Another example

```text
John

MANAGES

Alice
```

---

### Properties

Extra information stored on a node.

Example

```text
Employee

Name : Alice

Age : 28

Role : Engineer
```

---

# 15.4 Why Traditional RAG Struggles

Suppose three documents exist.

Document 1

```text
Alice works in HR.
```

Document 2

```text
Alice works on Project Phoenix.
```

Document 3

```text
Project Phoenix is managed by John.
```

Now ask:

```text
Who manages Alice's project?
```

The answer requires combining information from all three documents.

A normal Retriever may not retrieve all of them together.

---

# 15.5 How Graph RAG Solves This

Graph RAG follows relationships.

```text
Alice

↓

WORKS_ON

↓

Project Phoenix

↓

MANAGED_BY

↓

John
```

The answer is found by traversing the graph.

---

# 15.6 Traditional RAG vs Graph RAG

| Traditional RAG | Graph RAG |
|-----------------|-----------|
| Retrieves documents | Traverses relationships |
| Best for semantic search | Best for connected data |
| Uses embeddings | Uses graphs + embeddings |
| May miss relationships | Understands relationships |

Both approaches are valuable.

Many production systems combine them.

---

# 15.7 Where Graph RAG is Used

Graph RAG is useful when data is highly connected.

Examples:

- Company organization charts
- Healthcare records
- Fraud detection
- Supply chains
- Banking
- Social networks
- Research papers
- Knowledge bases

# 15.8 Neo4j

The most popular graph database is:

```text
Neo4j
```

Just as Chroma stores embeddings,

Neo4j stores:

- Nodes
- Relationships
- Properties

Example

```text
(Alice)-[:WORKS_IN]->(HR)
```

---

# 15.9 Cypher Query Language

Neo4j uses **Cypher** instead of SQL.

Example

```cypher
MATCH (e:Employee)-[:WORKS_IN]->(d:Department)
RETURN e, d
```

Don't worry about mastering Cypher.

You only need basic queries for Graph RAG.

---

# 15.10 Graph RAG Pipeline

```text
Documents
      │
      ▼
Extract Entities
      │
      ▼
Create Relationships
      │
      ▼
Store in Neo4j
      │
      ▼
User Question
      │
      ▼
Graph Search
      │
      ▼
Relevant Facts
      │
      ▼
LLM
      │
      ▼
Answer
```

---

# 15.11 LangChain + Neo4j

LangChain provides integrations with Neo4j.

A typical workflow is:

```python
from langchain_community.graphs import Neo4jGraph

graph = Neo4jGraph(
    url="bolt://localhost:7687",
    username="neo4j",
    password="password"
)
```

LangChain can then query the graph and send the retrieved facts to the LLM.

# Common Beginner Mistakes

### Mistake 1

Thinking Graph RAG replaces Vector RAG.

It doesn't.

Many production systems use both together.

---

### Mistake 2

Thinking every application needs Graph RAG.

Most simple document search systems work perfectly with traditional RAG.

Use Graph RAG when relationships are important.

---

### Mistake 3

Thinking Neo4j is an LLM.

It isn't.

Neo4j is a graph database used to store connected data.

---

# Key Takeaways

- A Knowledge Graph stores entities and their relationships.
- Graph RAG is useful when answers depend on connected information.
- Neo4j is the most popular graph database.
- Graph RAG complements traditional Vector RAG rather than replacing it.
- Many enterprise AI systems combine Vector Search with Knowledge Graphs.
