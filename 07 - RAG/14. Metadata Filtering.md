

## Introduction

So far, our Retriever searches **every document** stored in the Vector Database.

This works well for small projects.

But imagine a real company.

The company has documents from many departments.

For example:

- HR
- Finance
- Legal
- IT
- Sales

Now suppose an employee asks:

```text
Show me the HR leave policy.
```

Should the Retriever search Finance documents?

No.

It should search **only HR documents**.

This is where **Metadata Filtering** becomes useful.

---

# 14.1 What is Metadata?

Metadata means:

> **Data about the data.**

Imagine a PDF.

```text
Employee_Handbook.pdf
```

The document itself contains:

```text
Employees receive 24 paid leave days every year.
```

But we can also store additional information.

Example:

```text
Department : HR

Author : John

Year : 2025

Category : Policy
```

This extra information is called **Metadata**.

---

# 14.2 Why Do We Need Metadata?

Suppose our company has these documents.

| Document | Department |
|----------|------------|
| Leave Policy | HR |
| Payroll Policy | Finance |
| Laptop Policy | IT |
| Sales Incentives | Sales |

Now the user asks:

```text
Show HR policies.
```

Without metadata,

the Retriever searches every document.

With metadata,

it searches only:

```text
Department = HR
```

This makes retrieval:

- Faster
- More accurate
- More relevant

---

# 14.3 Metadata in a RAG Pipeline

```text
User Question
      │
      ▼
Metadata Filter
      │
      ▼
Search Matching Documents
      │
      ▼
Retriever
      │
      ▼
LLM
```

Notice something.

The filter is applied **before retrieval**.

The Retriever only searches the selected documents.

# 14.5 Python Example

Suppose we have two documents.

```python
documents = [
    "Employees receive 24 paid leave days every year.",
    "Quarterly financial reports are reviewed by Finance."
]
```

Create metadata.

```python
metadata = [
    {
        "department": "HR"
    },
    {
        "department": "Finance"
    }
]
```

---

# 14.6 Store Metadata in ChromaDB

```python
from langchain_chroma import Chroma

vector_store = Chroma.from_texts(
    texts=documents,
    embedding=embeddings,
    metadatas=metadata
)
```

Now every document stores:

- Text
- Embedding
- Metadata

---

# 14.7 Search with Metadata Filter

Suppose we only want HR documents.

```python
results = vector_store.similarity_search(
    query="Leave Policy",
    k=2,
    filter={
        "department": "HR"
    }
)
```

Display the results.

```python
for document in results:
    print(document.page_content)
```

Output

```text
Employees receive 24 paid leave days every year.
```

The Finance document is ignored.

# 14.9 Combining Multiple Filters

Filters can be combined.

Example:

```python
filter = {
    "department": "HR",
    "year": 2025
}
```

Now only documents matching **both conditions** are searched.

# Common Beginner Mistakes

### Mistake 1

Thinking metadata replaces embeddings.

It doesn't.

Metadata narrows the search, while embeddings find semantically similar documents.

---

### Mistake 2

Thinking metadata is part of the document text.

It isn't.

Metadata is additional information stored alongside the document.

---

### Mistake 3

Forgetting to store metadata during indexing.

If metadata isn't stored when documents are added, it can't be used for filtering later.

---

# Key Takeaways

- Metadata is information about a document.
- Metadata Filtering reduces the number of documents searched.
- It improves retrieval speed and accuracy.
- Common metadata includes department, author, date, category, and file name.
- Metadata Filtering is widely used in production RAG systems.
