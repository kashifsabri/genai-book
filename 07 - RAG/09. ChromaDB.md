

## Introduction

In the previous chapter, we learned how to use FAISS.

FAISS is excellent for learning because it is:

- Fast
- Lightweight
- Easy to use

However,

real-world RAG applications usually need more than just storing embeddings.

They also need to store:

- Original documents
- Metadata
- Collections
- Persistent storage

This is where **ChromaDB** becomes useful.

ChromaDB is one of the most popular Vector Databases for local RAG applications.

---

# 9.1 What is ChromaDB?

ChromaDB is an open-source Vector Database.

It allows you to store:

- Embeddings
- Original text
- Metadata

Unlike FAISS,

it is designed specifically for AI applications.

Think of it as a database built for RAG.

---

# 9.2 Why Use ChromaDB Instead of FAISS?

FAISS mainly focuses on fast similarity search.

ChromaDB provides additional features.

For example:

- Persistent storage
- Metadata filtering
- Collections
- Easy integration with LangChain

This makes it a better choice for many RAG applications.

# 9.6 Create a Chroma Vector Database

Import Chroma.

```python
from langchain_chroma import Chroma
```

Create the database.

```python
vector_store = Chroma.from_texts(
    texts=documents,
    embedding=embeddings
)
```

Internally,

Chroma:

```text
Documents
      │
      ▼
Generate Embeddings
      │
      ▼
Store Documents
      │
      ▼
Store Embeddings
```

Everything happens automatically.

---

# 9.7 Perform Similarity Search

Ask a question.

```python
query = "How many vacation days do employees receive?"
```

Search.

```python
results = vector_store.similarity_search(
    query=query,
    k=2
)
```

Display the results.

```python
for document in results:
    print(document.page_content)
```

Output

```text
Employees receive 24 paid leave days every year.

Employees can work remotely twice a week.
```

# 9.8 Store Metadata

One of ChromaDB's biggest advantages is metadata.

Suppose our documents belong to different departments.

```python
documents = [
    "Employees receive 24 paid leave days every year.",
    "Quarterly financial reports are reviewed by the Finance team."
]

metadata = [
    {"department": "HR"},
    {"department": "Finance"}
]
```

Store everything together.

```python
vector_store = Chroma.from_texts(
    texts=documents,
    embedding=embeddings,
    metadatas=metadata
)
```

Now every document also stores additional information.

---

# 9.9 Why is Metadata Useful?

Imagine asking:

```text
Show me the HR leave policy.
```

Without metadata,

documents from every department may be searched.

With metadata,

we can search only HR documents.

We'll learn metadata filtering in a later chapter.

---

# 9.10 Persistent Storage

Suppose you close your application.

Should you recreate the Vector Database every time?

No.

ChromaDB can save everything to disk.

```python
vector_store = Chroma.from_texts(
    texts=documents,
    embedding=embeddings,
    persist_directory="./chroma_db"
)
```

Now a folder named:

```text
chroma_db/
```

is created.

The next time your application starts,

you simply reconnect to the existing database.

---

# 9.11 Load an Existing Database

```python
vector_store = Chroma(
    persist_directory="./chroma_db",
    embedding_function=embeddings
)
```

No need to regenerate embeddings.

# Common Beginner Mistakes

### Mistake 1

Thinking ChromaDB is an LLM.

It isn't.

It stores and retrieves embeddings.

---

### Mistake 2

Thinking ChromaDB automatically answers questions.

It doesn't.

It retrieves relevant documents.

The LLM generates the answer.

---

### Mistake 3

Forgetting to enable persistent storage.

Without persistence, embeddings are recreated every time the application starts.
