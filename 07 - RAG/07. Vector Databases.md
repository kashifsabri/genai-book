

## Introduction

In the previous chapter, we learned that every document is:

- Loaded
- Split into chunks
- Converted into embeddings

Now another question arises.

> **Where are these embeddings stored?**

Can we store them in MySQL?

Can we use PostgreSQL?

Can we use MongoDB?

Technically, yes.

But they are **not designed** to efficiently search millions of vectors.

This is why we use a **Vector Database**.

---

# 7.1 What is a Vector Database?

A Vector Database is a special type of database designed to store and search **embeddings (vectors)**.

Instead of storing only rows and columns like a traditional database,

it stores vectors and can quickly find vectors that are most similar to a user's query.

Think of it as:

```text
Normal Database

Stores Records
```

↓

```text
Vector Database

Stores Embeddings
```

---

# 7.2 Why Can't We Use MySQL?

Imagine you have this table.

| Employee ID | Name | Department |
|--------------|------|------------|
| 101 | John | HR |
| 102 | Alice | Finance |

A SQL query works well.

```sql
SELECT *
FROM Employees
WHERE Department = 'HR';
```

This is called **exact matching**.

Now imagine embeddings.

```text
[0.12, -0.41, 0.88, ...]
```

How do you write SQL to find:

> "The vector most similar to this one"

Traditional databases are not optimized for this type of search.

Vector Databases are.

---

# 7.3 What Does a Vector Database Store?

A Vector Database usually stores three things.

### 1. The Embedding

Example:

```text
[0.32, -0.14, 0.77, ...]
```

---

### 2. The Original Text

Example:

```text
Employees receive 24 paid leave days every year.
```

---

### 3. Metadata

Example:

```text
Document:

Employee Handbook
```

```text
Page:

12
```

```text
Department:

HR
```

Metadata helps us filter search results later.

---

# 7.4 How Does a Vector Database Work?

Suppose our database contains these chunks.

```text
Chunk 1

Leave Policy
```

```text
Chunk 2

Working Hours
```

```text
Chunk 3

Dress Code
```

Each chunk already has an embedding.

Now the user asks:

```text
How many leave days do employees receive?
```

The process looks like this.

```text
Question
      │
      ▼
Embedding
      │
      ▼
Vector Database
      │
      ▼
Compare with Stored Embeddings
      │
      ▼
Return Most Similar Chunks
```

The returned chunks are then sent to the LLM.

---

# 7.5 Traditional Database vs Vector Database

| Traditional Database | Vector Database |
|----------------------|-----------------|
| Stores structured records | Stores embeddings |
| Searches using exact values | Searches using similarity |
| SQL queries | Vector similarity search |
| Best for business data | Best for AI applications |

Both databases solve different problems.

Many production applications use both together.

# 7.7 What is Metadata?

Suppose two documents contain the word:

```text
Leave
```

One belongs to:

```text
HR
```

Another belongs to:

```text
Finance
```

Now the user asks:

```text
Show HR leave policy.
```

Without metadata,

the Vector Database may return both documents.

With metadata,

we can filter the search.

Example:

```text
Department = HR
```

Only HR documents are searched.

Metadata becomes very important in production systems.

We'll learn metadata filtering later.

# 7.8 Python Example (Using Chroma)

Install the required libraries.

```bash
pip install langchain-chroma
pip install langchain-huggingface
pip install sentence-transformers
```

Import the required classes.

```python
from langchain_chroma import Chroma
from langchain_huggingface import HuggingFaceEmbeddings
```

Create an embedding model.

```python
embeddings = HuggingFaceEmbeddings(
    model_name="sentence-transformers/all-MiniLM-L6-v2"
)
```

Create some sample documents.

```python
documents = [
    "Employees receive 24 paid leave days every year.",
    "Office timings are from 9 AM to 6 PM.",
    "Employees can work remotely twice a week."
]
```

Create a Vector Database.

```python
vector_store = Chroma.from_texts(
    texts=documents,
    embedding=embeddings
)
```

Now the embeddings are stored inside Chroma.

Search for similar documents.

```python
results = vector_store.similarity_search(
    query="How many vacation days do employees get?",
    k=2
)
```

Display the results.

```python
for document in results:
    print(document.page_content)
```

Possible Output

```text
Employees receive 24 paid leave days every year.

Employees can work remotely twice a week.
```

Notice something.

We never manually calculated embeddings or similarity scores.

LangChain and Chroma handled everything for us.

# 7.9 Why Are Vector Databases Fast?

Imagine you have:

```text
2 Documents
```

Finding the closest one is easy.

Now imagine:

```text
10 Million Documents
```

Comparing the user's query with every embedding would be very slow.

Vector Databases use special indexing algorithms to make similarity search much faster.

You don't need to understand those algorithms right now.

Just remember:

> Vector Databases are optimized for fast similarity search.

# Common Beginner Mistakes

### Mistake 1

Thinking a Vector Database replaces MySQL or PostgreSQL.

It doesn't.

A Vector Database stores embeddings, while traditional databases store structured business data.

---

### Mistake 2

Thinking the LLM stores embeddings.

It doesn't.

Embeddings are stored in a separate Vector Database.

---

### Mistake 3

Thinking a Vector Database stores only vectors.

Most Vector Databases also store metadata and references to the original documents.

---

# Key Takeaways

- A Vector Database is designed to store and search embeddings.
- It performs similarity search instead of exact matching.
- It usually stores embeddings, original text, and metadata.
- Chroma, FAISS, and Pinecone are among the most popular Vector Databases.
- Vector Databases are a core component of every RAG system.
