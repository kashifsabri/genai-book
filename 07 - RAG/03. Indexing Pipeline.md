

## Introduction

Before a user can ask questions, a RAG system must first prepare all the documents.

This preparation process is called the **Indexing Pipeline**.

Think of it as building a searchable knowledge base.

Without indexing, the RAG system has nothing to search.

Indexing usually happens:

- Once when new documents are added
- Again only when documents are updated

It **does not run every time a user asks a question**.

---

# 3.1 What is the Indexing Pipeline?

The Indexing Pipeline converts raw documents into a format that can be searched quickly.

For example,

Suppose your company has these files.

```text
Employee Handbook.pdf

Leave Policy.pdf

HR Guidelines.pdf

Company Rules.docx
```

The RAG system cannot directly search these files.

Instead, it prepares them first.

---

# 3.2 Complete Indexing Pipeline

Every RAG system follows almost the same process.

```text
Documents
      │
      ▼
Load Documents
      │
      ▼
Split into Chunks
      │
      ▼
Generate Embeddings
      │
      ▼
Store in Vector Database
```

Let's understand each step.

---

# 3.3 Step 1 — Load the Documents

The first step is to read the documents.

These documents can be:

- PDF
- Word Documents
- Text Files
- HTML Pages
- Markdown Files
- CSV Files

Example:

```text
Employee_Handbook.pdf
```

The system extracts all the text from the file.

For example,

```text
Employees receive 24 paid leave days every year.

Working hours are 9 AM to 6 PM.
```

Now the document has become plain text.

---

# 3.4 Python Example

Using LangChain,

loading a PDF is very simple.

Install the required package.

```bash
pip install langchain-community
pip install pypdf
```

Load the document.

```python
from langchain_community.document_loaders import PyPDFLoader

loader = PyPDFLoader("Employee_Handbook.pdf")

documents = loader.load()

print(documents[0].page_content)
```

LangChain automatically extracts the text from the PDF.

---

# 3.5 Step 2 — Split the Document into Chunks

Imagine your PDF has 300 pages.

Should we store the entire PDF as one large document?

No.

Suppose a user asks:

```text
How many leave days do employees receive?
```

If we send all 300 pages to the LLM,

it will:

- Be slow
- Cost more
- Include lots of unnecessary information

Instead,

we split the document into **small pieces**.

These pieces are called **Chunks**.

Example:

```text
Chunk 1

Company Introduction
```

```text
Chunk 2

Leave Policy
```

```text
Chunk 3

Working Hours
```

Each chunk contains only a small amount of related information.

We'll study chunking in detail in a later chapter.

---

# 3.6 Step 3 — Generate Embeddings

Now every chunk is converted into an embedding.

Example:

```text
Leave Policy

↓

Embedding

↓

[0.42, -0.61, 0.13, ...]
```

The computer can now compare chunks mathematically instead of comparing plain text.

We'll study embeddings in the next chapter.

---

# 3.7 Step 4 — Store in a Vector Database

Finally,

all embeddings are stored in a Vector Database.

Think of it as a special database designed to store vectors instead of rows and columns.

Example:

```text
Chunk

↓

Embedding

↓

Vector Database
```

Now the documents are ready to be searched.

---

# 3.8 Why Do We Index Only Once?

Imagine your company has:

- 10,000 PDFs
- 2 million document chunks

Generating embeddings takes time.

If we repeated this work every time someone asked a question,

the system would become extremely slow.

Instead,

we perform indexing once.

Later,

the system simply searches the Vector Database.

This makes RAG much faster.

---

# 3.9 Real-World Example

Imagine a library.

Before people visit,

the librarian:

- Arranges books
- Labels shelves
- Creates a catalog

This work happens only once.

Later,

when someone asks:

```text
Do you have a Python book?
```

the librarian simply searches the catalog.

The books are **not reorganized again**.

The Indexing Pipeline works in exactly the same way.

---

# 3.10 What Happens After Indexing?

Once indexing is complete,

the Vector Database contains embeddings for every document chunk.

Now the system is ready.

When a user asks a question,

the Retrieval Pipeline begins.

```text
Question

↓

Generate Embedding

↓

Search Vector Database

↓

Retrieve Chunks

↓

LLM

↓

Answer
```

We'll learn this pipeline in the upcoming chapters.

# Common Beginner Mistakes

### Mistake 1

Thinking indexing happens every time a user asks a question.

It doesn't.

It usually happens only when new documents are added or existing documents are updated.

---

### Mistake 2

Thinking PDFs are stored directly inside the Vector Database.

The Vector Database stores **embeddings**, not the original PDF.

(Some vector databases can also store metadata and references to the original document.)

---

### Mistake 3

Thinking indexing is performed by the LLM.

It isn't.

Indexing is handled by the RAG system before the LLM is involved.

---

# Key Takeaways

- The Indexing Pipeline prepares documents before users ask questions.
- Documents are loaded, split into chunks, converted into embeddings, and stored in a Vector Database.
- Indexing is usually a one-time process.
- A well-designed indexing pipeline makes retrieval fast and efficient.
- After indexing is complete, the Retrieval Pipeline can quickly find relevant information.
