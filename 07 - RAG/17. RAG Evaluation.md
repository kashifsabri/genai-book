

## Introduction

Imagine you've built a RAG application.

It can:

- Load PDFs
- Create embeddings
- Store vectors
- Retrieve documents
- Generate answers

But an important question remains.

> **How do you know if your RAG system is actually good?**

Just because the LLM produces an answer doesn't mean the answer is correct.

A production RAG system must be evaluated.

Evaluation helps us answer questions like:

- Did the Retriever find the correct documents?
- Did the LLM answer correctly?
- Was the answer based on the retrieved documents?
- Did the system hallucinate?

---

# 17.1 Why RAG Evaluation Matters

Suppose the user asks:

```text
How many paid leave days do employees receive?
```

The Retriever returns:

```text
Office Timings
```

The LLM answers:

```text
Employees receive 30 leave days.
```

The answer looks reasonable.

But it's completely wrong.

Without evaluation,

you may never notice these mistakes.

---

# 17.2 What Should We Evaluate?

A RAG system has **two major parts**.

```text
Retriever
```

and

```text
LLM
```

So we should evaluate both.

---

## Retriever Evaluation

Questions to ask:

- Did it retrieve the correct documents?
- Were important documents missing?
- Were irrelevant documents retrieved?

---

## Answer Evaluation

Questions to ask:

- Is the answer correct?
- Is the answer supported by the retrieved documents?
- Did the LLM hallucinate?
- Is the answer complete?

---

# 17.3 Retrieval Metrics

Some common retrieval metrics are:

### Precision

Out of all retrieved documents,

how many were actually relevant?

Example

Retriever returns:

```text
10 Documents
```

Only:

```text
8 Documents
```

are relevant.

Precision

```text
8 / 10 = 80%
```

Higher Precision means fewer irrelevant documents.

---

### Recall

Out of all relevant documents,

how many did we retrieve?

Suppose:

```text
5 Relevant Documents Exist
```

Retriever finds:

```text
4 Documents
```

Recall

```text
4 / 5 = 80%
```

Higher Recall means fewer important documents are missed.

---

### Hit Rate

A simple but useful metric.

Question:

Did the correct document appear in the retrieved results?

Example

Top 5 retrieved.

Correct document is present.

Result

```text
Hit
```

Otherwise

```text
Miss
```

Many production systems track Hit Rate because it's easy to understand.

---

# 17.4 Answer Evaluation

Retrieval may be perfect,

but the LLM can still generate a poor answer.

Evaluate questions like:

- Is the answer factually correct?
- Is every claim supported by retrieved documents?
- Did the model invent information?
- Is the answer complete?

---

# 17.5 Hallucination Detection

Suppose the retrieved document says:

```text
Employees receive 24 paid leave days.
```

The LLM answers:

```text
Employees receive 30 paid leave days.
```

This information was never retrieved.

This is called a **Hallucination**.

A good RAG system minimizes hallucinations by grounding answers in retrieved context.

---

# 17.6 Manual Evaluation

The simplest evaluation method.

Create a list of questions.

Example

```text
What is the leave policy?

Who manages Project Phoenix?

What are office timings?
```

Ask each question.

Check:

- Was retrieval correct?
- Was the answer correct?
- Was anything hallucinated?

Manual evaluation is useful for small projects.

---

# 17.7 LLM-as-a-Judge

For larger systems,

manual evaluation becomes difficult.

Instead,

another LLM can evaluate the answers.

Example

Input

```text
Question

Retrieved Context

Generated Answer
```

Judge Prompt

```text
Is the answer fully supported by the retrieved context?

Answer only:

Correct

Partially Correct

Incorrect
```

This approach is called **LLM-as-a-Judge**.

Many modern AI teams use it for automated testing.

---

# 17.8 RAG Evaluation Workflow

```text
Question
      │
      ▼
Retriever
      │
      ▼
Retrieved Documents
      │
      ▼
LLM
      │
      ▼
Generated Answer
      │
      ▼
Evaluation
```

The evaluation step checks both:

- Retrieval Quality
- Answer Quality

# 17.9 Common Evaluation Tools

Several open-source tools can evaluate RAG systems.

Some popular ones are:

- RAGAS
- DeepEval
- LangSmith
- TruLens

You don't need to master them now.

Just know that they help automate RAG evaluation.

# Common Beginner Mistakes

### Mistake 1

Thinking a fluent answer is always a correct answer.

Good writing does not guarantee factual accuracy.

---

### Mistake 2

Evaluating only the LLM.

A poor answer may actually be caused by poor retrieval.

Evaluate both the Retriever and the LLM.

---

### Mistake 3

Ignoring hallucinations.

Every production RAG system should monitor whether answers are supported by the retrieved context.

---

# Key Takeaways

- RAG systems should evaluate both retrieval quality and answer quality.
- Precision, Recall, and Hit Rate are common retrieval metrics.
- Answers should be grounded in the retrieved documents.
- Hallucinations occur when the LLM generates unsupported information.
- Tools like RAGAS, DeepEval, LangSmith, and TruLens help automate evaluation.
