

## Introduction

In the previous chapter, we learned that every document chunk is converted into an embedding before being stored in a Vector Database.

But what exactly is an embedding?

Why can't we simply search using plain text?

Let's understand.

---

# 4.1 Why Can't Computers Understand Text?

Imagine these two sentences.

Sentence 1

```text
I want to learn Artificial Intelligence.
```

Sentence 2

```text
I want to study AI.
```

As humans,

we know both sentences mean almost the same thing.

But for a computer,

they are just different words.

It cannot naturally understand that:

```text
Artificial Intelligence

=

AI
```

or

```text
Learn

≈

Study
```

To compare meaning,

computers first convert text into numbers.

---

# 4.2 What is an Embedding?

An embedding is a **list of numbers that represents the meaning of a piece of text.**

Example

```text
Artificial Intelligence
```

becomes

```text
[0.42, -0.18, 0.77, 0.31, ...]
```

Don't worry about the numbers.

You don't need to understand them.

The important thing is:

> Similar meanings produce similar embeddings.

---

# 4.3 Why Are Embeddings Needed?

Suppose your document contains:

```text
Employees receive 24 paid leave days every year.
```

Now a user asks:

```text
How many vacation days do employees get?
```

Notice something.

The document contains:

```text
paid leave
```

The question contains:

```text
vacation days
```

The words are different.

But the meaning is similar.

A keyword search may fail.

An embedding search succeeds because it compares **meaning**, not exact words.

---

# 4.4 How Are Embeddings Created?

An embedding model reads the text and converts it into a vector.

```text
Sentence
      │
      ▼
Embedding Model
      │
      ▼
Vector (Embedding)
```

Example

```text
Employees receive 24 paid leave days.

↓

[0.13, -0.41, 0.77, ...]
```

Every chunk gets its own embedding.

---

# 4.5 One Embedding Per Chunk

Remember,

during indexing,

we split documents into chunks.

Example:

```text
Employee Handbook

↓

Chunk 1

Company Introduction
```

↓

```text
Chunk 2

Leave Policy
```

↓

```text
Chunk 3

Working Hours
```

Each chunk receives its own embedding.

```text
Chunk 1

↓

Embedding 1
```

```text
Chunk 2

↓

Embedding 2
```

```text
Chunk 3

↓

Embedding 3
```

This allows the RAG system to retrieve only the relevant chunk instead of the entire document.

---

# 4.6 Where Are Embeddings Stored?

After creating embeddings,

they are stored inside a Vector Database.

```text
Chunk

↓

Embedding

↓

Vector Database
```

The original text is usually stored as metadata or alongside the embedding.

Later,

when a question is asked,

the Vector Database searches these embeddings.

---

# 4.7 Python Example

Install the required package.

```bash
pip install sentence-transformers
```

Load an embedding model.

```python
from sentence_transformers import SentenceTransformer

model = SentenceTransformer(
    "all-MiniLM-L6-v2"
)
```

Create an embedding.

```python
embedding = model.encode(
    "Employees receive 24 paid leave days."
)

print(embedding)
```

Output (shortened)

```text
[0.21, -0.65, 0.81, ...]
```

---

# 4.8 Using LangChain

In real-world RAG applications,

LangChain simplifies this process.

Install the required packages.

```bash
pip install langchain-huggingface
pip install sentence-transformers
```

Create an embedding model.

```python
from langchain_huggingface import HuggingFaceEmbeddings

embeddings = HuggingFaceEmbeddings(
    model_name="sentence-transformers/all-MiniLM-L6-v2"
)
```

Generate an embedding.

```python
vector = embeddings.embed_query(
    "Employees receive 24 paid leave days."
)

print(vector[:5])
```

LangChain hides much of the boilerplate code, making it easier to build RAG applications.

we'll use:

```text
sentence-transformers/all-MiniLM-L6-v2
```

# Common Beginner Mistakes

### Mistake 1

Thinking embeddings store the original sentence.

They don't.

They store a numerical representation of the sentence's meaning.

---

### Mistake 2

Thinking embeddings understand grammar like humans.

They capture semantic similarity mathematically.

---

### Mistake 3

Thinking different embedding models produce identical vectors.

Each model creates its own vector representation.

---

# Key Takeaways

- Embeddings convert text into numerical vectors.
- Similar meanings produce similar embeddings.
- Every document chunk gets its own embedding.
- Embeddings are stored in a Vector Database.
- Embeddings allow RAG systems to search by meaning instead of exact words.
